# Plan — PE-008-verified-idempotent-webhooks

## Approach
`POST /webhooks/pixelforge` sits outside every middleware group. Its one route middleware checks the HMAC of `<t>.<raw body>` with `WebhookSignature`, a sign-and-verify pair in `app/Support/Pixelforge`. The controller then parses the raw bytes (never `$request->input()`) into `WebhookDeliveryData`. `HandlePixelforgeWebhookAction` runs one transaction that locks the matched generation and writes the `pixelforge_webhook_events` row with `ON CONFLICT DO NOTHING`. Only a new row hands its snapshot to PE-006's `TransitionGenerationAction`, so PE-007's ledger settles or releases exactly once, and a small change to the transition's identity rule (task 4) makes AC14's provider-id fallback work.

| --- | --- | --- |

| `InvalidWebhookSignatureException` | `app/Support/Pixelforge/Exceptions/` | Extends `RuntimeException`, with `public readonly WebhookSignatureFailure $reason`. `because(WebhookSignatureFailure)`. The message never holds the header, the body or the secret. |
| `WebhookSecretNotConfiguredException` | `app/Support/Pixelforge/Exceptions/` | Extends `RuntimeException`, with `missing()`. Thrown by both `sign()` and `verify()` when the secret is null or `''`, so the HMAC is never computed with an empty key (AC6). PE-010's AC4 reuses it. |
| `WebhookSignature` | `app/Support/Pixelforge/` | The constructor takes `#[Config('pixelforge.webhook_secret')] ?string` and `#[Config('pixelforge.webhook_tolerance_seconds')] int`. **`sign(string $payload, int $timestamp): string`** returns the header value `t=<ts>,v1=<hex>`. **`verify(string $payload, ?string $header): void`** checks, in order: the secret is configured; the header is present and not blank (`missing`); it parses (`malformed`); `hash_equals` on the HMAC of the header's `t` as sent, `.` and the payload (`mismatch`); and \|now − t\| ≤ tolerance (`stale`). The signature is checked before staleness, so `stale` always means a genuine but old delivery. **Parsing:** comma-separated `key=value` parts, each trimmed. `t` must be digits only and `v1` non-empty. A repeated `t` or `v1` is malformed, because several `v1`s are out of scope, and unknown keys are ignored. **Clock:** `CarbonImmutable::now()`, which `travelTo()` and `setTestNow()` both freeze. **Consumers:** the middleware, `DeliversPixelforgeWebhooks` and the unit test; PE-010's fake later. |
| `VerifyPixelforgeWebhookSignature` | `app/Http/Middleware/` | Calls `verify()` on `getContent()` and `Pixelforge-Signature`. **Not configured:** `Log::critical` with `event_id` (the header or null), and an empty 500. **Invalid:** `Log::warning` with `reason` and `event_id`, and an empty 400. It never logs the body, the signature header or the secret. |
| `webhooks.php` | `routes/` | `POST /webhooks/pixelforge` → `HandlePixelforgeWebhookController`, named `webhooks.pixelforge`. Its only middleware is `VerifyPixelforgeWebhookSignature`. |
| `app.php` | `bootstrap/` | `withRouting(then: …)` loads `routes/webhooks.php` outside the `web` group, so there is no session, cookie, CSRF, Inertia, auth or throttle. Global middleware still applies. TrimStrings only cleans the parsed input bags, so the raw bytes stay untouched. |
| `HandlePixelforgeWebhookController` | `app/Http/Controllers/` | Invokable. Builds `WebhookDeliveryData::from()` from `getContent()` and the three `Pixelforge-Event-*` / `-Delivery-Attempt` headers. On `InvalidWebhookDeliveryException`, it calls `Log::error` with the message and the exception's `context()` and answers an empty 400. Otherwise it runs the action and answers an empty 200 (requirements §4, PE-014 AC8). **No Form Request and no `validate()`:** a failed validation redirects (302) a request that does not ask for JSON, and validated input is TrimStrings-cleaned rather than the signed bytes. **Unexpected exceptions** go to the framework handler, which reports them and answers 500 (AC23). |
| `WebhookEventType` | `app/Support/Pixelforge/Enums/` | `GenerationProcessing` = `generation.processing`, `GenerationSucceeded`, `GenerationFailed`, `Ping` = `ping`. `generationStatus(): ?GenerationStatus` is null for `Ping`. **Consumers:** `WebhookDeliveryData` (a generation type needs `data.object`) and the action (AC18). |
| `WebhookDeliveryData` | `app/Support/Pixelforge/DataTransferObjects/` | `readonly`. `from(string $payload, ?string $headerEventId, ?string $headerEventType, ?string $headerDeliveryAttempt): self`. **Fields:** `eventId`, `type` (as received), `knownType` (`?WebhookEventType`), `snapshot` (`?GenerationSnapshot`, from task 5), `deliveryAttempt` (`?int`), `headerEventId`, `headerEventType`. **Rules:**<br>• `json_decode` with `JSON_THROW_ON_ERROR`, and the result must be an array.<br>• `id` and `type` must be non-empty strings of at most 255 characters with no NUL byte. pdo_pgsql cuts a string at a NUL, so two ids could collide.<br>• A known generation type needs `data.object` as an object. `ping` and unknown types ignore `data` (AC7).<br>• From task 5, `GenerationSnapshot::from(data.object)` runs, and its exception becomes `unreadableSnapshot`.<br>• The attempt header must be an integer from 1 to 2,147,483,647, or it becomes null. This means a DB error is never possible.<br>Unknown fields are ignored. |
| `InvalidWebhookDeliveryException` | `app/Support/Pixelforge/Exceptions/` | Extends `InvalidArgumentException`. `notJson(JsonException)`, `notAnObject()`, `invalidField(string $path, string $expected)`, `missingObject(string $eventId)` and `unreadableSnapshot(string $eventId, ?string $generationId, InvalidGenerationSnapshotException $previous)`. `context()` returns `{event_id: ?string, generation_id: ?string}`. Messages name the field, never echo its value, and never include the body. The snapshot's own message can hold a single field value. |
| `PixelforgeWebhookEvent` | `app/Domain/Generation/Models/` | `#[Fillable]` for `event_id`, `type`, `delivery_attempt` and `generation_id`. `CREATED_AT = 'received_at'` and `UPDATED_AT = null`, so `fillAndInsertOrIgnore` stamps the time received. `#[DateFormat('Y-m-d H:i:sP')]` like `Generation`. Casts: `integer` and `immutable_datetime`. `type` stays a plain string, because unknown types are stored too. There are no relations and no factory: only the action writes rows, and tests send real deliveries. |
| `HandlePixelforgeWebhookAction` | `app/Domain/Generation/Actions/` | Injects `TransitionGenerationAction`. `execute(WebhookDeliveryData $delivery): void`. It first logs a header mismatch (AC24), then runs one `DB::transaction`:<br>1. For a generation type, it matches the row under `lockForUpdate` (see Matching).<br>2. It writes the event row with `fillAndInsertOrIgnore`. If 0 rows are inserted, it returns: the delivery is a duplicate.<br>3. A ping returns. An unknown type logs a warning and returns. | `TransitionGenerationAction` | `app/Domain/Generation/Actions/` | Task 4 reorders `classifySnapshot`'s identity check: provider id first, ULID only while none is stored (see Matching). **Matching** (tasks 4, 5 and 7). Lookups run inside the transaction, under `lockForUpdate`. A non-ULID value is never queried: pdo_pgsql cuts a string at a NUL, so `<ULID>\0x` would otherwise match the real row.

| `metadata.generation_id` | `data.object.id` | Row | Result |
| --- | --- | --- | --- |
| The row's ULID, and the row has no provider id | any | that row | Applied, and the provider id is stored (AC13). |
| The row's ULID | equals the stored provider id | that row | Applied (AC8). |
| The row's ULID | differs from the stored provider id | that row | Recorded against it and refused. The transition logs both ids at error level (AC15). |
| Absent | equals a stored provider id | that row | Applied, with the task 4 warning (AC14). |
| Malformed, too long, or a ULID with no row | equals a stored provider id | that row | Recorded against it and refused as another generation's. The id contradicts the row, which is not merely missing data. |
| Anything without a ULID match | matches no row | none | Recorded without a generation, with a warning that carries the event id, type, `generation_id` and `provider_id` (AC22). |

**Response policy**

| Case | Status | Persisted | Log |
| --- | --- | --- | --- |
| No secret configured, for any request | 500 | nothing | critical |
| The signature is missing, malformed, mismatched or stale | 400 | nothing | warning, with the reason and the header event id |
| A signed body that cannot be read: the envelope (AC7) or the snapshot | 400 | nothing | error, with the event id and `generation_id` when known |
| A duplicate event id | 200 | nothing new | none |
| A ping | 200 | the event | none |
| An unknown type or an unknown generation | 200 | the event | warning |
| Identity conflict, out-of-order or D-09 | 200 | the event (and D-09's cost) | the transition's existing logs |
| Applied | 200 | the event and the transition | none |
| An unexpected exception (ledger, bad rate, row changed) | 500 | rolled back | the framework's report |

## Decisions log (requirements §5)
Use the next free D-numbers after the highest one in `requirements.md` at commit time. PE-007 took D-26, so today that is D-27 onwards. Task 4 adds D-27, and task 12 adds D-28 to D-30.

| # | Decision | Why |
| --- | --- | --- |
| D-next (task 4) | A snapshot without `metadata.generation_id` is identified by a stored provider id equal to its `id`. Our ULID is required only while no provider id is stored. A present `generation_id` that differs from the row's ULID is still refused. This narrows PE-006 AC12. | The stored provider id is unique, and it was itself written from a ULID-matched snapshot, so it proves identity just as well. Refusing would strand a generation that Pixelforge bills, with its hold, for good, because PE-014 polls rows with a provider id until they are terminal. A contradicting id is still refused: then the data is wrong, not just incomplete. |
| D-next (AC27, response policy) | A verified event for an unknown generation or of an unknown type gets 2xx and is recorded. A bad signature, or a signed body we cannot read, gets 400 and nothing is persisted. A missing secret or an unexpected failure gets 500 and is rolled back. | Pixelforge retries every non-2xx 5 more times over 27 min 40 s. The row always exists before submit (D-05), so for an unknown generation or type a retry can never succeed. An unreadable body is not recorded, so a dashboard resend after a fix is processed. A 500 is retried because a retry can help (a transient failure), or because the operator must act (a missing secret). |
| D-next (AC27, body over headers) | Dedupe and routing use the signed body's `id` and `type`. The `Pixelforge-Event-*` headers are informational: a disagreement is logged, and the body wins. | Only the body is covered by the HMAC. A replayed delivery with rewritten headers could otherwise dodge dedupe or be routed as another type. |
| D-next (AC27, record every event) | Every verified event id is recorded, including pings, unknown types and unknown generations, in the same transaction as its state change (D-07). | It is one dedupe rule with no exceptions. A redelivery is always a silent no-op, never a second warning. The rows show what Pixelforge actually sent, including the dashboard's test ping. |

## Tests
Feature tests live in `tests/Feature/Webhooks/` and use `RefreshDatabase`, except the concurrency test. Every request goes through `DeliversPixelforgeWebhooks` with the exact raw body. The trait sets a known secret, so the developer's `.env` never matters, prevents stray HTTP, and freezes time. Amounts are asserted with `assertSame` on exact ints. "Changes nothing" means comparing `rawGenerationRow()` and `ledgerEntriesFor()` before and after, with a 1-minute `travel()` in between. Every rejection also asserts that no event row exists.

Shared test helpers (`tests/Concerns/`):
- `DeliversPixelforgeWebhooks` (new) uses `InteractsWithGenerations` and `InteractsWithGenerationSnapshots`:
  - `setUpDeliversPixelforgeWebhooks()` sets `pixelforge.webhook_secret` to a test `whsec_…`, calls `Http::preventStrayRequests()` and travels to a fixed instant.
  - `pixelforgeEvent(string $type, ?array $object, ?string $eventId = null)` builds the docs envelope with a fresh `evt_…` id.
  - `deliverPixelforgeWebhook(string $body, array $headers = [])` posts the raw body with `call()`. It signs the body at `now()` unless a `Pixelforge-Signature` is given (null omits the header). The event id and type headers default to the body's, and the attempt defaults to 1. `deliverPixelforgeEvent(array)` JSON-encodes the envelope first.
  - `pixelforgeSignatureFor(string $body, int $timestamp, ?string $secret = null)`.
  - `storedWebhookEvents()` returns the raw rows, ordered by `id`.
  - `givenTheSubmittedLighthouseGeneration()` applies the Lighthouse's queued snapshot, as PE-009's create response will, so it stores `gen_<ULID>`.
- `InteractsWithGenerationSnapshots`: `lighthouseSucceededObjectFor(Generation)` returns the raw object, and `lighthouseSucceededSnapshotFor()` now wraps it.
- `WaitsForDatabaseLocks` (new, task 10): the child database env, `waitUntilBackendsWaitOnALock()` and the JSON result reader, moved unchanged from `TransitionGenerationActionConcurrencyTest`, which now uses the trait.

## Risks
- **PR size is well over the ≈400-line budget.** The estimate is ≈2,200 changed lines, excluding `.agent-workflow`: ≈650 production and docs, and ≈1,550 tests. The story's ~600 leaves out most of the tests. One PR per story is the rule even above the budget (`.agent-workflow/CLAUDE.md`), so this ships as one PR, and the PR description names the cut point.
  - The cut is after task 1.
    - PR A (task 1, ≈420) holds the signature, the config and their unit tests.
    - PR B (tasks 2–12, ≈1,800) holds the endpoint and everything else.
  - PR A is safe on its own: no route uses the class yet.
  - Tasks 2–4 answer 200 to generation events without applying them. They are intermediate commits inside PR B and must never ship apart from task 5.
- **The story's "400 = no retry" is wrong.** The docs count only 2xx as delivered, so a 400 is retried too. The 400 for unreadable bodies is kept because nothing is recorded, so a dashboard resend after a parser fix is processed. Pixelforge stops after 6 attempts, and PE-014 recovers the generation.
- **AC14 narrows PE-006 AC12.** The task 4 decision row and the updated conflicts test make it explicit. A malformed or foreign `generation_id` with a matching provider id is still refused. That case is only possible if Pixelforge itself is inconsistent.
