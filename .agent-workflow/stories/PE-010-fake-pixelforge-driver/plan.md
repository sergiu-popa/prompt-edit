# Plan — PE-010-fake-pixelforge-driver

## Approach
A `FakePixelforgeClient` implements PE-009's contract. It persists each accepted create in its own `fake_pixelforge_generations` table, keyed by the idempotency key, and it rejects `[blocked]` and `[overloaded]` before storing anything. An `AdvanceFakeGenerationJob` on the normal database queue then moves each generation from queued to processing to terminal, with configurable delays. After each step a `FakeWebhookSender` signs the envelope with PE-008's `WebhookSignature` and POSTs it to `http://app:8080/webhooks/pixelforge`. Usage is drawn from inside the PE-002 estimate's own bounds, seeded by the key, so it is reproducible and never above the hold. Image URLs are root-relative temporary signed routes, so one URL loads in both dev and E2E. The app refuses to boot with the fake in production, `.env.example` selects it locally, and `make setup` generates a local webhook secret.

## Domain
All classes are `final` unless noted, and every file declares `strict_types`. Everything only the fake uses lives in `app/Support/Pixelforge/Fake/`, so the whole fake is one folder. Its driver sits in `Drivers/` beside the HTTP one. Its job stays in `Fake/` rather than `app/Jobs/`, because it is the fake's internals, not app work. Support already reads Billing value objects (`GenerationSnapshot`). The fake also calls the Billing estimator, because its usage must be bounded by the same code that sets the hold.

## Tests
Feature tests use `RefreshDatabase` unless noted, and every test runs with stray HTTP prevented (`Tests\TestCase`). Amounts are exact ints asserted with `assertSame`. Provider cost and charge are computed in the test from the snapshot's usage (n$/token 5,000 / 10,000 / 40,000 / 12,500, then `intdiv(p × 125 + 99, 100)`), never by the class under test. **Lighthouse windows:** provider [278,200,000; 365,720,000], charge [347,750,000; 457,150,000].

Shared helper `tests/Concerns/InteractsWithFakePixelforge` (new; it composes `InteractsWithGenerations` for `LIGHTHOUSE_PROMPT`):
- Constants: `FAKE_WEBHOOK_SECRET` (a test value, not `whsec_` shaped) and `FAKE_WEBHOOK_URL` = `http://app:8080/webhooks/pixelforge`.
- `setUpInteractsWithFakePixelforge()` sets the driver to `fake` and the secret. From task 6 it also registers `Http::fake([FAKE_WEBHOOK_URL => responder])`, and the default responder answers 200.
- `answerFakeWebhooksWith(Closure)` swaps the responder: a 500, `Http::failedConnection()`, or one that travels time per request. The responder is swapped rather than re-faked, because the first `Http::fake` stub that matches wins.
- `lighthousePayload(?string $generationId = null, ?string $prompt = null)` builds a `CreateGenerationPayloadData`: Landscape, High, `https://example.com/style.png`, and a fresh lowercase ULID unless one is given.
- `createThroughFake(CreateGenerationPayloadData)` resolves `FakePixelforgeClient`. From task 8 it calls `Queue::fake([AdvanceFakeGenerationJob::class])` first, as `createGenerationFor()` does for the submit job. Its docblock says so.
- `runFakeLifecycle()` (task 8) runs every held-back job in push order until none is left. Before each one it travels by that job's `delay`, so the timestamps advance as on the worker.
- `fakeWebhookRequests()` returns the recorded POSTs to `FAKE_WEBHOOK_URL` in order. `fakeGenerationRow(string $providerId)` returns the stored row.
- `replayFakeWebhooks()` (task 9) posts each recorded webhook to its URL's path, with exactly its captured headers (`transformHeadersToServerVars`) and its exact body. It returns the responses.

## Risks
- **PR size is well over the ≈400-line budget.** The estimate is ≈2,800 changed lines, excluding `.agent-workflow` and the PNG: ≈900 of production code, config and docs, and ≈1,900 of tests. The story's ~650 leaves out most of the tests. One PR per story is the rule (`.agent-workflow/CLAUDE.md`), so this ships as one PR, and the PR description names the cut point.
  - The cut is after task 10.
    - PR A (tasks 1–10, ≈2,050) is a working fake that succeeds every generation and is the local and E2E default.
    - PR B (tasks 11–16, ≈750) adds `[fail]`, `[slow]`, `[duplicate]`, expiry with `[expire]`, chaos with `[succeed]`, and the decisions.
  - This follows the story's split, except that AC 12 moves to PR B: `[succeed]` means nothing until chaos exists.
  - If split, task 16's rows ship with the PR that holds their code.
- **Relative `image_url`.** `GenerationSnapshot` accepts any non-empty string, so nothing breaks today. PE-012 must render `image_url` as given and never require an absolute `http(s)` URL. Real URLs are absolute, and both work in `<img src>`.
- **Existing dev `.env` files** keep their old values: `PIXELFORGE_DRIVER` empty means `http` with the real dev key. After merge, set `PIXELFORGE_DRIVER=fake`, run `make webhook-secret` (it keeps an existing `whsec_…`, which the fake can sign with just as well) and `make restart-worker`. The PR description says so. The Engineer never edits the main checkout's `.env`.
- **The worker reads `.env` once.** Any change to the driver or the secret needs `make restart-worker`. That is why `setup` ends with it.
- **The in-network hop itself** (worker → `app:8080`) is only exercised on the dev and CI stacks, because PHP tests use `Http::fake`. PE-011's E2E pins it. The orchestrator's E2E run on the main stack is the first live check. `trustHosts()` is skipped in `local` and in tests, so `Host: app:8080` is accepted.
- **The `sync` test queue runs the lifecycle inline**, inside the create. That is why `createThroughFake()` holds the job back. The round-trip test deliberately does not, to prove the nested chain works.
- **Duplicate copies may share a `t`** when both are sent within one second. Each copy is still signed at its own send time, and the test travels between copies to prove it.
- **Deliberate simplifications, each documented in D-next:**
  - chaos is decided per generation, not per webhook;
  - `[succeed]` does not suppress a chaos 503 or duplicates;
  - a stored key with new params that contain a rejection keyword gets the rejection, not 409.
  - The real API's order is unknown, and PE-015's live smoke guards drift.
- **The production-boot test runs `php artisan` in a subprocess.** It relies on config not being cached (`bootstrap/cache/config.php`), which the test suite already requires. A thrown boot error exits non-zero with the message on stderr.
- **`fake_pixelforge_generations` grows locally**, and `migrate:fresh` clears it. Keys are fresh ULIDs, so a reset never replays old rows.
- **Story status.** When this plan is committed, `story.md` moves to `planned`.
